# 일일 투자 브리프 재설계 — 시장 읽기 렌즈 + 어제 대비 변화

**상태:** 설계 승인됨 (2026-06-24, Noah) · 구현 대기(writing-plans)
**대상 레포:** `noah-market-briefs` (cron 프롬프트 계약은 `<cron 러너 설정>` + `docs/ARCHITECTURE.md`)

## Context / 배경

4개 cron(KR/US × 장전/마감)이 매일 시장 브리프를 Slack + 정적 아카이브(Vercel)로 발행한다. 시스템·데이터 수집·디자인·발행 파이프라인은 감사 결과 **이미 견고**하다(소스 디시플린·결정적 스냅샷·데이터 구동 렌더·정렬 교정 완료).

남은 레버는 브리프의 **출력 가치(인사이트·유용성)**다. Noah 우선순위(2026-06-24):

- 특정 **보유종목 민감도는 보류** — 지금은 일반 **"주식 투자 / 투자" 관점**의 매일 브리프(한국/미국·장전/마감)를 받아보는 것 자체가 핵심.
- 그 핵심 가치 = **"시장 읽기 + 어제 대비 변화"**. 매일 받아보며 시장 흐름 감을 익히는 저널.

이 스펙은 기존 "보유논지 민감도" 섹션을 **종목 비의존 "투자 관점 렌즈"**로 재구성하고, **"어제(직전 같은 윈도) 대비 변화"**를 더해 아카이브 누적이 **시장 흐름 저널**이 되게 한다.

## Goals / Non-goals

**Goals**
- 매일 똑같이 평가하는 **투자 관점 렌즈**(위험선호·금리·환율·변동성[·섹터]) 일일 신호 + 레벨.
- **Δ vs 어제**: 각 렌즈·핵심지표에 직전 같은 윈도 대비 변화(↑/↓/=) + 상단 `changes[]`("어제 대비 핵심 변화 2-3줄").
- **장전/마감 차별화**: 장전=닥칠 환경(예측), 마감=받은 결과(회고).
- 아카이브 누적이 "위험선호 며칠째 회복" 같은 **시장 흐름 저널**로 읽힘.

**Non-goals (지금)**
- 특정 보유종목 추적(보류, 삭제 아님).
- 새 외부 데이터 스크래핑(한국 채권/수급/V-KOSPI 보강 등) — 기존 스냅샷 그대로.
- 투자 권유·가격 목표. (소스 디시플린·미확인 표기 유지.)

## Design

### A. 투자 관점 렌즈 (`theses[]` 칸 재활용)

기존 `theses[]`(종목 카드) 구조를 **그대로 재사용**하되 내용이 종목명 → **투자 차원(렌즈)**으로 바뀐다. 렌더러는 name을 모르고 동작하므로 **렌더 변경 최소**.

- **고정 렌즈 세트(매일 평가)**: `위험선호` · `금리·duration` · `환율·달러/원화` · `변동성·헤지` · (선택)`섹터·브레드스`.
- 렌즈 객체 = `{name(차원), signal(오늘 읽기), level(1-3), delta{dir,text}(선택), body}`.
- **데이터 매핑**(기존 스냅샷으로 충족): 위험선호←지수/선물, 금리←10Y·국채선물, 환율←DXY·USD/KRW, 변동성←VIX·V-KOSPI(미확인 시 그대로).
- 섹션 제목: **"보유논지 민감도" → "투자 관점 읽기"**.
- KR/US 공통 코어 + 시장별 강조(KR은 원화 비중↑, US는 duration·credit↑). 렌즈 세트는 공통, 본문 강조만 다름.

### B. 어제 대비 변화

- **상단 `changes[]`** (2-3줄): 직전 같은 (market, window) 브리프 대비 시장이 뭐가 바뀌었나(예: "어제 risk-off→오늘 반등", "VIX 19→16 진정").
- **각 렌즈·핵심지표 `delta`**: `{dir: up|down|flat, text}` — ↑/↓/= 칩 + 한 줄.
- **비교 기준 = 직전 같은 (market, window) 브리프**. 아카이브의 직전 JSON이 곧 메모리.

### C. 장전/마감 차별화

같은 스키마, **프레이밍·강조만** 윈도별로:
- **장전**(예측): "오늘 닥칠 환경" — 간밤 컨텍스트 + 오늘 watch 강조. 렌즈는 "오늘 받을 압력".
- **마감**(회고): "오늘 받은 결과" — 뭐가 왜 일어났나 + 렌즈 레벨이 어떻게 변했나.

## Architecture (units)

각 단위는 한 가지 책임, 독립 테스트 가능.

1. **데이터 스키마** (`data/**/*.json`): `theses[]` item에 `delta` 추가, 최상위 `changes[]` 추가. **백워드 호환** — 없으면 graceful(섹션 미표시).
2. **`scripts/render_market_brief.py`**: ⓐ `changes[]` 블록 렌더, ⓑ 렌즈/지표 `delta` 칩 렌더, ⓒ 섹션 제목 변경. 렌즈는 기존 thesis 카드 구조 재사용 → 변경 최소.
3. **`scripts/build.py`**: **Phase 1 변화 없음**(load/정렬/가드 그대로). **Phase 2**: `(market, window, lens_name)`별 레벨 히스토리 집계 → ● 추이·스트릭 데이터를 render에 전달.
4. **프롬프트/계약**: cron이 **직전 같은 윈도 JSON을 읽어** 렌즈 평가·`delta`·`changes[]` 작성, 윈도별 프레이밍 적용. 정본 = `docs/ARCHITECTURE.md`(+ SKILL.md 미러). **런타임 cron 프롬프트(`<cron 러너 설정>`) 수정은 classifier 차단 → Noah가 적용**(레포엔 계약 문서만).
5. **`assets/brief.css`**: `changes` 블록 · `delta` 칩 · (Phase 2)히스토리 점 스타일. 기존 Lamplight Ledger 톤 유지.

## Data flow

```
cron(스냅샷 데이터 + 직전 같은 윈도 브리프 JSON 읽기)
  → 렌즈 평가 + delta + changes 작성
  → data/YYYY/MM/DD/<window>.json
  → scripts/build.py (HTML + index 재생성)
  → git push → Vercel 배포 + Slack 링크
```

## Error handling / edge cases

- **직전 브리프 없음**(첫날/신규 시장): `delta` 생략, `changes`는 생략하거나 "직전 브리프 없음" 1줄. graceful.
- **레거시 브리프**(delta/changes 필드 없음): 렌더 정상, 새 섹션만 미표시(백워드 호환).
- **소스 디시플린 유지**: 렌즈 평가도 데이터 근거 없으면 `미확인`, 출처·날짜 강제, 추론 금지.
- **malformed/누락**: 기존 `build.py` 견고성(skip-not-crash)이 그대로 보호.

## Testing

- **TDD**(비협상): 렌더가 `changes[]`·`delta` 렌더, 없으면 미표시(백워드) 검증. 렌즈 카드 재사용·섹션 제목 검증. (Phase 2) 히스토리 집계 단위 테스트.
- 기존 18 테스트 유지 + 신규. `python -m unittest discover -s tests`.
- 첫 실제 cron run으로 delta/changes 자동 검증(스키마 맞는 JSON 생성 확인).

## Phasing (증분)

- **Phase 1 (즉시·이번 구현)**: 스키마(`delta`,`changes`) + 렌더 + CSS + 계약 문서(ARCHITECTURE.md). **새 데이터 수집 0**, 각 브리프 직전 1개만 읽음. → 렌즈 재구성 + 어제 대비 변화 + 윈도 프레이밍.
- **Phase 2 (다음 증분)**: `build.py` 렌즈 히스토리 집계 → ● 추이·스트릭(시장 흐름 저널 완성).
- **Phase 3 (옵션)**: 주간 시장 회고 롤업.

- 비교 기준: **직전 같은 (market, window) 브리프**.
